# firstmargin UI rules

## Page tab URL and history state — 2026-10-19

Page-level tab selections are derived from the route or a validated search parameter. Staff Console uses `staffTab=competitions|users` with Moderation as the default; Member Hub uses `memberTab=updates|workshops` with Early access as the default. Standalone authentication tabs use `/login` and `/signup`, while the embedded sign-in modal keeps local mode state. Studio's existing `writingTab`, `writingFormat`, and `draftFormat` selections now create history entries. Selecting a tab preserves unrelated query parameters, and Back, Forward, direct links, and reload restore the selected view. Invalid tab values fall back to each page's existing default. Other page tab groups already use route or URL state.

## Cursor list pagination — 2026-10-19

Cursor-backed lists request the next page as the reader approaches the end of the relevant scroll pane. Page feeds use the application scroll pane; comments and notifications use their modal or thread scroll area; collection and series pickers load more options inside the open Select list. A failed next-page request retains loaded items and offers Try again at the end of the list. No list displays a Load more button. Existing filters, cards, routes, and data contracts remain in use.

## Profile member request card — 2026-10-19

For writer accounts, Member requests appears as a read-only compact card in the Profile summary grid, using the same surface, border, radius, and padding as the adjacent stat cards. It shows the saved On/Off status and three-per-month limit. Edit profile holds the Turn on/Turn off control; its staged value is applied by the page's single Save action through the existing profile update API. Readers do not see either control. Edit profile also previews a chosen profile picture locally and uploads it only on Save; Back leaves it unchanged. Valid pictures are JPG, PNG, WebP, or GIF up to 8 MB. A successful save updates the public profile and account avatar while retaining the existing name, biography, and interests workflow.

## Staff and profile page headers — 2026-10-19

The staff console keeps its existing Operations eyebrow and Staff console title and adds a secondary description of reports, competitions, and user accounts. The personal Profile page uses the shared PageHeader with Your space, Profile, and a short description above the unchanged identity block; the account display name remains visually the same as a secondary heading. Studio and access/loading views retain their existing header behavior.

## Staff console — 2026-10-18

The staff console uses Moderation, Competitions, and Users underline tab buttons matching Studio and Library, with arrow/Home/End keyboard selection. Their content toolbars use shared serif section headings—Reports, Competitions, and Users—on the left and Filters at the right; Add competition stays beside the competition filter. Moderation has a right-aligned Filters button for Pending, Reviewing, and Dismissed; each report remains a list row. Review report opens the selected report in a native modal with the existing required note and actions. Resolved reports open a read-only view. Competitions lists Ongoing and Past records behind a right-aligned Filters button; Add competition sits to its left. Each competition row links across its card surface to `/explore/competitions/:id`; its separate score/results action opens `/staff/competitions/:id/judging`. This full page lists every entry and shows each moderator's scores for the selected entry. Collective Choice includes the fixed roster, pending slots, and original submitter. Moderators add only their own missing score; admins fill a missing moderator slot or edit an existing moderator score only while judging remains open. Score entry and editing use a shared modal with prefilled values for edits. A recorded Collective Choice score has no moderator edit action. Legacy judge scores remain readable, with own-score editing for the acting judge and existing-score editing for admins during judging. A legacy admin's separate add action appears only when the entry has no recorded score. Add competition shows a decorative plus before its label for administrators and opens the existing creation form in a modal. Users lists 25 accounts per page, newest first, with a right-aligned Filters button containing All and one choice per stored role; Premium is labeled Members. Changing role or resetting filters returns to page one. Eligible active regular, member, exclusive-writer, and moderator rows expose the shared three-dot menu with Edit role and an unavailable Remove user item. Edit role opens a native modal with a vertical radio list, marks the current role, and saves only the allowed transition; Members may become Exclusive writers or Moderators. A staff member cannot change their own role. The existing staff role gates apply. Remove user remains unavailable pending the full suspension and appeal lifecycle required by the moderation policy.

## Reader-facing terminology — 2026-10-18

Use **Story** for the full-length `article` format and **Short** for the `short` format. Use **Appreciate** for the engagement action, **Remove appreciation** for its reversal, and **appreciation/appreciations** for counts. Apply these names to visible copy, accessible names, loading and error states, search tabs, writing controls, and notifications. Keep existing `post`, `article`, `like`, and `short-read` identifiers where they are part of routes, API fields, stored values, CSS selectors, URL state, or internal code. “Post” remains an ordinary verb for submitting a comment or question. The backend naming pass is separate.

## Button hover text — 2026-10-18

Enabled buttons, navigation links, and other button-like controls show a browser-native hover title from their current accessible label or visible text. An explicit title takes precedence. Disabled buttons continue to use the existing contextual explanation tooltip.

## Home carousel and page tabs — 2026-10-17

All DiscoveryPostCard article grid cards, including Home story carousels and Author Published work, share a 400 px height. Grid cards without a cover image render the shared abstract ImageBox fallback in the same 180 px cover region, so covered and coverless cards keep aligned content in mixed rows. List cards without a cover retain their text-only composition. ImageBox artwork has distinct story, collection, series, entry, competition, and inline-image variants without visible words or logos; descriptive names remain available to assistive technology. Avatar fallbacks use name-derived abstract artwork rather than visible initials. Titles clamp after two lines; excerpts own the remaining space and render into that flexible region above bottom-aligned engagement controls. Cards without excerpts keep the footer at the bottom. Author's public writer response includes an excerpt derived from the stored body, using the discovery text extractor, so the grid can show it. The carousel prop remains available for future carousel-specific layout. Mobile primary navigation uses a Browse link to Collections, whose mobile tabs also reach Series. Page-level tab rows remain at the top of the application scroll area; Explore's Trending, Questions, and Competitions selector follows the same rule.

## Question detail controls and analytics prompt — 2026-10-17

The question detail follow action reads the current viewer's question state: Follow question changes to Unfollow question after a successful follow and back after unfollow. Its report trigger uses the shared ghost Button with a leading flag icon and Report text, while its accessible name remains “Report this question.” The Studio advanced analytics modal places Become a member at the right edge of its content area.

Application pages save the `#main-content` scroll position per browser history entry in the current tab. New navigation starts at the top; Back and Forward restore the destination entry's position, including when content loads after navigation. Keep recently departed entries so Forward can restore them.

Modals that show the shared header Close icon omit a redundant footer Cancel button. Dismiss with Close, Escape, or an available backdrop; pending-write guards still apply. Keep Back when it changes a modal step. Inline edits retain their existing Cancel controls; Edit profile uses the shared page Back control without a bottom Cancel button.

## Series browsing and editing — 2026-10-15

The primary Series page at `/series` has Stories and Shorts pill tabs with URL state (`type=short`; Stories is the default). Its cards and Create a series dialog follow existing page, card, modal, and button styles. The series-card grid uses responsive columns with a 420 px minimum track; empty tracks remain reserved when a page has only one series, so its card retains the same column width as a multi-card page. Intermediate and small layouts use one column. Cards are content-driven. Inside the existing 420 px grid tracks, the reusable card shows a cover or shared image fallback that fills its identity column, a prominent serif title, a separate author line, a divided description, and up to three ordered chapter titles from the list response. It stacks the chapter preview below the identity when narrow and splits them at 360 px of inner card width. The title link covers the card, with one separate action menu; long text clamps or truncates. Create a series first asks whether the writer wants Posts or Shorts and does not load eligible writing until that choice is made; Back returns to the format choice without closing the dialog. Eligible writing is selected through the app's popover-style multi-select dropdown, never native checkboxes. The dropdown supports individual choices, Select all, and Clear all. Its anchor remains stationary while choices change; after the dropdown closes, the form shows the chosen posts or shorts below it in the reading order established by selection. The Shorts page links to the Shorts series tab and keeps its short feed without an embedded series grid. A series contains only published posts of its selected format; existing short series remain short series. Owners edit a series through an Edit series modal on detail, where they can update the required title and optional description, add eligible existing posts, remove entries, and change reading order. Save is enabled for valid text-only or order changes when at least two parts remain. Series detail uses compact numbered rows with the shared item menu; post rows include a cover when available. `/series/:id` is canonical for new navigation, while `/shorts/series/:id` remains usable. Direct entry Back from the new detail route returns to Series.

Series cards expose the shared three-dot ActionMenu with owner-only Edit series and Delete series, Share link, and Not interested. Edit series navigates to detail and opens the existing edit modal; deletion uses a confirmation dialog and the owner-scoped series delete API. Not interested hides only that card locally. The card body remains a link to detail, while the menu trigger and actions operate independently. There is no series-saving or series-reporting contract, so those actions are not offered.

Released owner posts and shorts expose Add to series in the shared list-card overflow menu, Studio management menu, full article actions, and compact short-reader actions. The shared dialog lists only the signed-in writer's existing matching-format series, paginates owned choices, reports loading/error/empty/full/already-assigned states, and restores focus. A post already in a series cannot be moved implicitly; the writer must remove it from its current series first. Other writers' content and unpublished content do not receive the public card/detail action.

On full article detail, the series link appears only after the article body, before comments. It identifies the story as part of the named series, includes its current part number when available, and opens the series page. The short reader shows the same series link after its body inside the scrollable reading pane whenever the short has series context. Neither reader links directly to the next part from this section.

## General rules

- Content card grids reserve the responsive columns that fit their container even when they contain only one item. Shared `card-grid` variants use `auto-fill`; fixed-column grids keep their explicit breakpoint columns. Item count must not make a lone card expand across otherwise empty tracks.

- Displayed content titles and public identity names capitalize their first alphabetic character while preserving the rest of the user-provided text. This presentation rule applies consistently to posts, shorts, collections, series, component title fields, usernames, and display names; it does not rewrite stored values or URL handles.
- Below 768 px, where the bottom navigation is shown, page and Account-sheet list/section separators made with bottom borders are hidden. Spacing still separates content; tab-strip dividers, card outlines, field borders, and selected-tab underlines remain visible. Desktop separators are unchanged.
- Question list rows use more vertical padding below 768 px to keep adjacent questions distinct without dividers: full question cards use 36 px on each side, and Home's Hot Questions rows use 24 px. Wider-screen spacing remains unchanged.
- Page and section headings keep adjacent actions in a right-hand column and align them vertically to the center of the complete title and description block from the small-screen breakpoint upward. Below that breakpoint, the action wraps to a new left-aligned row after the heading content so narrow screens do not compress the heading or button. Heading text remains left-aligned and wraps within its column. Shared PageHeader enforces this across application pages, and local heading/action rows follow the same rule. Home Writer's picks, Browse categories, Browse collections, Short reads, Top authors, and Hot Questions use this behavior and carry short descriptions in the existing secondary-text style. Writer's picks and Browse categories use grid-style DiscoveryPostCard in horizontal carousels; story and category tracks support touch swipes and continuous desktop mouse dragging without scroll snap, hide native scrollbars, and show only a swipe/drag text cue when content overflows. Inserted sections use 24 px outer vertical margins and 32 px vertical padding. Author, Profile, and Member Hub early-release article grids use one column below 540 px, two from 540 px, and three from 1024 px. Article grid covers retain the shared 16:9 ratio; grid cards now use a 180 px cropped cover and the fixed height and space-aware excerpt rule above. The feed tab row stays sticky at the top of the application scroll pane beneath the global navigation with 12 px top padding; it keeps native horizontal touch scrolling with proximity snap points and contained horizontal overscroll, and shows a trailing fade only while more tabs remain off-screen.
- Home Top authors keeps its ranked profile-link rows and shared 40 px Avatar. Its grid uses one column below 540 px, two from 540 px, and four from 1024 px for at most four writers. Long names and featured-story counts truncate within their rows instead of overflowing the grid.

- Use semantic HTML before adding roles.
- Every interactive state includes default, hover, pressed, focus-visible, disabled, loading, and error behavior where relevant. Native buttons and shared button links without a component-specific hover utility receive a restrained brightness change on hover; disabled controls do not. Borderless action buttons use a theme-aware translucent hover surface so the response remains visible over both surface and alternate backgrounds.
- Do not use color as the only indication of state.
- Prefer clear hierarchy and whitespace over extra containers.
- Avoid cards nested inside cards.
- Use sentence case in UI copy.
- Controls use direct labels: “Save draft,” not “Proceed.”
- Destructive actions name the object affected and require proportionate confirmation.
- Do not show success before the server confirms persistence unless the action is explicitly optimistic and reversible.
- Comment Like/Unlike uses the common icon-only pending treatment: keep the transparent surface, heart/count placement, and full-opacity count; fill only the heart with the muted token. Retain aria-busy and repeat protection through confirmed refresh.

## Button styles and target sizes

- Standard actions reuse Button, navigation CTAs use ButtonLink, and icon-only actions use IconButton with a required accessible label. Named styles are primary, secondary, ghost, action, menu, disclosure, danger, and selector; Pill uses the selector/selected-primary presentation. Never infer behavior or permissions from a button's visible name.
- Shared sm/md have 44 px minimum targets; lg has 48 px. Small means compact label/padding, not a smaller hit area. Native feature controls use the same button-target minimum while retaining their approved shapes and typography. Shared action links use explicit theme text colors to survive the global anchor-inheritance rule. Button retains aria-busy, returned-promise repeat protection and forwarding of native attributes/refs.
- Disabled buttons, including native feature buttons, show a hover explanation through the application-level DisabledButtonTooltip. Callers with a specific rule set `data-disabled-reason`; the tooltip also recognizes busy state, form validation, and first/last movement boundaries, then uses a general unmet-requirements message. The hover explanation does not alter the disabled action or button appearance.
- Icon-only controls have a minimum 44 × 44 px target (48 × 48 for lg). Desktop Join keeps its approved 36 px minimum. Navbar Clear search keeps its 32 px visible cross with an expanded 44 px hit area. Cover choices and other larger feature controls retain their larger minimums. Inactive legacy cards/toolbars are not migrated.
- Article membership/audio controls and active tool icons use the inverted text token/currentColor on action backgrounds in both themes. Navbar notification badges use the same inverted token. Existing tool-rail, auth, vote-card, tab, filter, modal, comment and editor layouts remain distinct. [Button duplicate list](button-style-duplicates.md) maps local controls to exact, near, or absent reusable matches; it does not authorize a wholesale migration.

## Fonts and editorial hierarchy

- ModalHeader's title column fills the space beside Close. Without a subtitle, vertically center the title against the 44 px Close target instead of reserving a second text row. With a subtitle, preserve the existing top-aligned title/subtitle layout. Title text retains its existing left alignment.

- The shared Save story dialog uses the existing collection Select. Collection options retain their visibility badge and append “Already added” when the current story or short is already in that collection; the selected duplicate state is handled by the final action rule below.

- In the shared Save story dialog, Add to a collection remains enabled even when the story is already in one or more collections. Selecting an already-containing collection disables the final action and changes its label to “Already in collection”; other collection choices remain available.

- All 14 modal families and the desktop Inbox reuse ModalHeader: 20 px bold Libre Baskerville title, optional 12 px secondary subtitle, bottom divider, 16 px phone/24 px wider gutters, 12 px vertical padding, and a borderless 44 px Close button with hover/focus feedback. Preserve existing title IDs, close labels, focus refs, placement, motion, and form content. Every modal with an exposed backdrop closes on outside click, Escape, and Close; a full-screen modal with no outside backdrop target retains its existing Close/Escape behavior. Existing in-flight write guards remain. Account and sign-in titles are visible; mobile Search places its title row above the animated search field with one Close control. This approved 2026-10-10 contract supersedes earlier modal-specific sans-serif/uppercase/hidden header descriptions. Detailed inventory: [modal audit](modal-audit.md).

- Page and article titles use the display serif.
- Navigation, filters, controls, forms, and metadata use the body sans.
- Full Story paragraphs and quotes use Source Serif 4 in the published reader and the editor. Short body text retains DM Sans; headings retain Libre Baskerville. Font size and line height remain surface-specific.
- Article body defaults to at least 17 px with generous line height.
- Limit long-form text width to `--width-reading`.
- Avoid more than three typographic levels in a single card or compact region.
- Small uppercase labels are optional, not the default section-heading pattern.
- Use tabular numbers for analytics, timers, ranks, and vote counts.

## Cards

A card exists only when grouping or interaction benefits from a bounded surface.

### Article card

Required content:

- Article title
- Writer identity
- Cover or an intentional text-only layout
- Reading time or content format
- Publication/freshness context
- Optional topic and one primary quality/context signal

Rules:

- The title or explicit stretched link owns navigation.
- Shared discovery post cards use a semantic stretched headline link for the excerpt and remaining card space, while only the writer avatar/name open the writer profile; publication dates and reading times are plain text. Article category chips open the existing `/search?q=<category>` post search. List-card category chips stay on one line beside the engagement controls; only whole chips that fit the remaining width are visible, and they return when the card widens. Menu, appreciation, comment, and cover targets remain independent. Only the grid writer name links to the writer; its reading time remains plain text without changing the compact presentation. Short-card previews omit tag chips, while the detailed reader retains tags and its existing interaction. Explore's Article of the Day follows the same identity/metadata distinction, with independent menu and engagement controls.
- Story list-card titles retain 20 px Libre Baskerville with 1.3 line height and `-0.015em` tracking; compact grid titles retain their existing 16 px scale. FeaturedPostCard headlines keep their responsive size and `-0.04em` tracking with 1.18 line height. These spacing rules give wrapped headings room without changing card structure or title destinations.
- ShortCard restores keyboard focus from its reader with a card-wide focus ring, keeping wrapped title text free of fragment outlines. ShortCard retains its 250 px maximum standalone width and 380 px height. Dedicated short-card grids use fluid columns with a 170 px minimum, four-column cap, and compact 2:3 portrait ratio; they use two columns from 360 to 407 px and one centered card capped at 250 px below 360 px. Every card now splits into a near-black title section and a slightly lighter excerpt section. The title section displays the first nonempty tag in a single truncated uppercase line, or a short accent rule when no tag exists, beside the existing overflow menu. Titles clamp to two lines at every size. The lower section gives the excerpt all space above a divided footer and dynamically clamps to the full lines that fit. The footer puts the writer avatar and first name on the left, with a one-line truncated first name and compact appreciation/comment controls on the right. Writer links retain the full name as their accessible label. The shared grid is used on Home, Shorts, Search, Author, Profile, Studio, collection detail, Saved, and short-format History. Cover previews, short reader, menu actions, routes, APIs, and stored data retain their existing behavior. The detailed short reader shows only complete tag pills that fit one row; hidden pills are not focusable, and the row collapses when none fit.

- Fluid ShortCard titles use 18 px display type with 1.3 line height and a two-line clamp; standalone titles retain 22 px with the same line height. Cover-free fluid cards give the title section a 35% minimum height, while the compact two-column 360–407 px layout uses 42%; the section grows to fit the tag/menu row and both title lines when a narrow card needs more room. The excerpt uses the remaining space. Standalone cover-free cards use a 42% minimum; covered cards size the title section to its content.
- Short summary responses provide up to 800 excerpt characters so the ShortCard's existing line clamp can fill the available preview area. Article and legacy-format summaries remain limited to 220 characters; short text still stops when the source body ends.
- Studio Shorts retain the shared short-card grid and presentation but replace discovery overflow actions with WritingPostMenu, using the same Edit, Unpublish/Republish, and Delete actions as studio story rows. Discovery and reading surfaces open collection choices through Save; Studio menus retain owner actions. Public profile and discovery short cards retain discovery actions.
- Short-read detail author avatars and names open the writer profile; the separate reading-time label stays plain text. Identity links use the stored handle with the existing username fallback and dismiss the reader. Comments remain inline: the compact Comments disclosure initially hides both the composer and discussion list. The fixed footer has four evenly spaced actions: heart with appreciation count, comment icon with count, icon-only Save, and icon-only Share. All four omit visible action words at every width and retain accessible names. The Save icon fills when active and opens the shared save dialog on every activation. All retain 44 px targets and existing engagement, sign-in, dialog, and focus behavior. Share opens the same centered native modal used throughout the app, with a content-specific heading, Close, Copy Link, and Share on X for the canonical `/post/:id` URL. It opens above the existing reader; dismissal returns focus to Share and preserves the reader. Clipboard failures keep the options available for retry.
- Save and overflow actions remain separate buttons.
- Do not make a non-semantic outer `div` the only clickable target.
- Use a maximum of two metadata rows.
- Active post-card covers use a stable 16:9 ratio when their width changes in narrow list cards, short cards, featured cards on narrow screens, and competition entries. Discovery article grid covers use a fixed 180 px cropped region so text remains visible within fixed-height cards. Studio row thumbnails use their existing 5:4 shape. Desktop discovery list covers retain their 140 px height, and desktop featured covers continue to fill the text-defined row. Text content determines card height where a fixed ratio would clip titles or actions.
- Avoid equal-height card grids when content density varies significantly.
- Below 540 px, list-style discovery cards hide the description and show abbreviated publication date and reading time immediately after writer identity on the left, with dots between the name, date, and reading time. The compact author name uses the same muted text color as the date and reading time. Image-bearing list cards show the full-width 16:9 cover first, then that combined writer/metadata row and a title capped at two lines. Center the author within a compact menu row; the menu keeps its 44 px touch target without stretching that row, and the title begins 8 px below it. Comfortable Home feed cards use 16 px vertical insets below 540 px, including the first card. Image-bearing cards leave 16 px below the cover, 8 px from the metadata/menu row to the title, and 8 px before the topic/action footer, reducing the gap between consecutive cards while keeping their divider. From 540 px, image-bearing cards keep the side-by-side composition and full date/read-time text: a 140 px-high, 200 px-wide cover with a 24 px gap through the middle widths, then a 240 px-wide cover with a 32 px gap from 1024 px. Text-only list cards keep their stacked layout below 768 px. The narrow-screen footer reserves separate columns for wrapping topic chips on the left and appreciation/comment controls on the right, keeping tags clear of the actions. Long names, titles, and topics wrap within the card.
- On Home at every width, Writer's picks and Browse categories reuse grid-style DiscoveryPostCard inside touch-scrollable carousels with continuous mouse dragging; category choices scroll horizontally. Feed and section dividers remain visible. Short reads appear in groups of at most four after the sixth feed story and every eighth story thereafter when more shorts are available. Dedicated short-card grids opt ShortCard into a 2:3 portrait ratio and fluid width; their grids use a 170 px minimum track and cap at four columns, so cards grow slightly on wide screens. Fluid cards use a two-line title, a dynamically clamped excerpt, and a single compact writer/action footer. The first tag or a tagless accent line appears above the title; preview dates remain omitted. A 285 px minimum height keeps the excerpt visible in ordinary columns; from 360 to 407 px, 270 px minimum cards use tighter padding and row spacing. Below 360 px, a single centered card keeps the normal fluid spacing and 285 px minimum height. Standalone short cards and mixed article layouts keep their existing presentation.
- The dedicated Shorts page requests the next cursor page as the reader approaches the end of its grid in the application scroll pane. Existing short-card skeletons show while it loads; no Load more button appears. Topic and sort filters continue to use their existing URL parameters and feed query, and an empty filtered state appears only once the cursor feed is exhausted.
- All direct post appreciation controls use the shared `AppreciationButton`: borderless transparent action, 15 px heart, 12 px count, 44 px minimum target, outlined unselected heart, and filled heart with action text color when selected. Discovery list/grid/short cards, Article of the Day, article pages, and short-read modals share this presentation, including pending and keyboard-focus states. Existing authentication, optimistic updates, rollback, and menu commands are preserved.
- Writer-profile article cards use shared `PostEngagementControls` beside wrapping topic chips in the existing footer, replacing the static appreciation/comment sentence. Like/unlike retains reader-specific selected state and optimistic rollback; comments open the existing comments modal without navigating to the article. Covers, reading/date metadata, serif titles, tag links, grid, and article navigation are preserved.
- Appreciation and comment controls show an icon and numeric count with accessible names and 44 px targets. Appreciation uses the existing server-backed set/unset action and pending state. Comments open the shared comment list/composer in a native modal without opening the story or expanding the card. The modal blocks background interaction, contains keyboard focus, scrolls internally on narrow/short screens, and supports Close, Escape, and backdrop dismissal with focus returned to the comment button. Its scroll pagination makes the full thread accessible; comments load only when the modal opens. Guests can read comments and receive the existing sign-in prompt to participate.
- Discovery-card overflow menus use leading icons for Save, Share, recommendation explanation, Not interested, and Report. Appreciation lives on the card rather than in this menu; keyboard navigation and trigger-focus restoration remain available.
- Wrapped reading-order post lists preserve 24 px above each card after the first, keeping author metadata clear of the previous divider. `DiscoveryPostCard` retains its default first-card alignment; collection lists explicitly enable flush top spacing only for index zero.
- List discovery cards group linked writer identity above publication date/reading time with an 8 px row gap and a 20 px gap before the headline. The overflow trigger is a quiet 44 px control with a centered three-dot SVG, hover feedback, and keyboard focus; it has no raised border/shadow. Shared appreciation/comment controls use borderless transparent surfaces, 12 px counts, subtle hover feedback, and 44 px targets.

Staff and public competition list/detail tags use those display names for `readers` and `hybrid` legacy modes as well as the new stored types; legacy judges-only records retain a Judges label. ## Buttons

### Hierarchy

- **Primary:** one dominant action per local decision area.
- **Secondary:** important alternative with lower emphasis.
- **Tertiary/text:** navigation or low-risk supportive action.
- **Quiet/icon:** compact action whose icon is familiar and has an accessible name.
- **Danger:** destructive action; never use it as decoration.

Rules:

- Minimum pointer target: 44 × 44 px where layout permits; never below 40 × 40 px for icon-only controls.
- Labels start with a verb when an action occurs.
- Icon-only buttons require `aria-label` and usually a tooltip.
- Async loading uses `aria-busy` plus `disabled`, retaining the existing label/icon instead of inserting a spinner or loading label. For icon-led buttons, the shared rule in `global.css` fills/strokes only SVG icons with `--color-text-muted`; non-SVG glyphs use `data-button-icon` and the same muted color. Labels/counts stay at full opacity, surfaces retain their normal styling, and the cursor is wait. Text-only buttons retain the existing 60% accent/40% surface pending fill. Shared `Button`, `AppreciationButton`, and native feature buttons use this same treatment in both themes. Existing optimistic saved/followed/voted state and counts may still update. Validation/permission-disabled states remain separate. Keep actionable menus visible until successful completion; failures restore the control for retry. Preserve recovery views during no-data query refetch via retainRetryView so Retry itself remains visible and busy; initial loads retain their skeletons. Source inventory, boundaries, and browser coverage live in [button loading audit](button-loading-audit.md).
- Reuse `Button` primary/secondary pills, borderless `action` for icon/text controls, full-width `menu` rows, and borderless `disclosure` controls for collapsible sections. Disclosure callers own aria-expanded, aria-controls, and content visibility; the variant supplies a chevron by default, retaining optional trailingIcon. Leading/trailing icon slots mark decorative glyphs for pending styling. Existing native controls with SVGs receive the common treatment automatically; mark text glyphs with `data-button-icon`. Compact engagement controls use `data-button-style="action"` for transparent borders/surfaces, including selected states, while preserving geometry and keyboard focus. Dropdown triggers, primary pills, and dedicated circular icon controls retain their normal structure.
- Disabled controls must remain legible and should explain unmet prerequisites nearby.
- A button triggers an action; a link navigates.
- Do not pair primary and ghost buttons mechanically on every surface.

## Responsive rules

- Standalone login, signup, and verification use one unframed form column up to 448 px wide on the theme canvas, with the existing pen brand link above. Authentication has no Back button; the brand link returns home. Verification digits share the available width; the Google control follows the available form width up to 400 px and recalculates on resize.

- Design for narrow width first, then enrich composition.
- Do not rely on hover for essential functionality.
- Prevent horizontal page scroll at 320 px CSS width.
- Major dialogs become full-height drawers when their content cannot fit comfortably.
- Tables require a mobile transformation or intentional scroll container.
- Long words, URLs, writer handles, and article titles must wrap safely.

## Accessibility baseline

- Meet WCAG 2.2 AA contrast and interaction expectations.
- Keep one main content landmark per rendered route; the application shell owns scrolling, while route content owns its main landmark.
- Include a skip-to-content link.
- Provide visible `:focus-visible` treatment.
- Maintain logical heading order.
- Give meaningful images useful alt text; decorative images use empty alt deliberately.
- Respect reduced motion and system color preference. With no explicit saved Light/Dark choice, startup and the shared theme hook use `prefers-color-scheme` and follow its live changes; automatic system selection must not be stored as a manual preference. Explicit Light/Dark Settings choices persist under `ink-theme` and take priority across routes/reloads. Use system theme clears that override and immediately resumes system detection and live updates. Browsers without preference detection fall back to dark.
- The global reduced-motion mode disables non-essential animation and transition timing and turns off smooth scrolling; interaction and focus behavior remain available.
- Announce asynchronous form results with appropriate live regions.
- Test primary flows using keyboard only and at 200% zoom.
